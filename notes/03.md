# Урок 3. XOR, одноразовый блокнот, потоковые и блочные шифры

## Биты, байты, UTF-8

- **Бит**: 0 или 1. **Байт**: 8 бит, число от 0 до 255. В Python это тип `bytes`, например `b'AB'`.
- **UTF-8**: латиница занимает 1 байт, кириллица 2: `'А'.encode() == b'\xd0\x90'` (208, 144). Поэтому шифруем байты: тогда зашифровать можно что угодно — текст, картинку, exe.
- `int.from_bytes(b'AB', 'big')` $= 65 \cdot 256 + 66 = 16706$, обратно — `to_bytes`.

## XOR

$a \oplus b = 1$, когда биты разные. Пример: $5 \oplus 3 = 101_2 \oplus 011_2 = 110_2 = 6$.

Свойства:

$$a \oplus a = 0, \quad a \oplus 0 = a, \quad a \oplus b = b \oplus a, \quad (a \oplus b) \oplus c = a \oplus (b \oplus c)$$

$$\Rightarrow (a \oplus k) \oplus k = a.$$

Шифрование и расшифрование — одна и та же операция (инволюция).

## XOR-шифр

Каждый байт данных XOR-ится с байтом ключа, ключ повторяется по кругу: $c_i = d_i \oplus k_{i \bmod L}$.

Пример: `b'hello'` ⊕ `0x01`: `68 65 6c 6c 6f` → `69 64 6d 6d 6e` = `b'idmmn'`. Ещё один XOR с тем же ключом возвращает `b'hello'`.

Короткий повторяющийся ключ — это тот же Виженер, только на байтах, и ломается он так же.

## Одноразовый блокнот (шифр Вернама)

Три условия:
1. ключ **истинно случайный**;
2. ключ **не короче** сообщения;
3. ключ используется **ровно один раз**.

Тогда шифр **абсолютно стойкий** (Шеннон): при любом шифртексте $c$ любой открытый текст $p$ той же длины равновероятен, потому что ему соответствует ровно один ключ $k = p \oplus c$. Перебор ключей выдаёт все возможные тексты, и понять, какой из них настоящий, нельзя.

**Атака при повторе ключа (crib dragging):**

$$c_1 \oplus c_2 = (p_1 \oplus k) \oplus (p_2 \oplus k) = p_1 \oplus p_2 \oplus (k \oplus k) = p_1 \oplus p_2 \oplus 0 = p_1 \oplus p_2.$$

Ключ исчезает. Если угадать кусок $p_1$ (crib), сразу получаем кусок $p_2 = (c_1 \oplus c_2) \oplus p_1$. В демо угадали `привет` и получили `секрет`.

## ГПСЧ и криптостойкие генераторы

- **ГПСЧ (PRNG)**: детерминированный алгоритм. Одно и то же **зерно (seed)** всегда даёт одну и ту же последовательность. `random` (вихрь Мерсенна) годится для игр и симуляций, но не для ключей.
- **LCG**: $x_{n+1} = (a x_n + c) \bmod m$. Зная $a, c, m$ и одно значение, можно предсказать все следующие. Пример: $a = 1103515245$, $c = 12345$, $m = 2^{31}$, seed $= 1$ → $x_1 = 1103527590$.
- **CSPRNG**: выход непредсказуем, даже если известны все предыдущие значения. Это `secrets` и `os.urandom` (энтропия от ОС).

**Правило:** ключи, соли и токены генерируем только через `secrets`.

## Потоковый шифр

Короткий ключ (seed) разворачивается ГПСЧ в бесконечную **гамму** $g_0 g_1 g_2 \dots$, и данные XOR-ятся с ней: $c_i = d_i \oplus g_i$.

Гамму удобно делать генератором с `yield`: он ленивый и бесконечный. Для каждого `encrypt` создаётся свежий генератор с тем же seed. Расшифрование = повторное шифрование, потому что гамма получается та же.

Это одноразовый блокнот «для бедных»: ключ короткий, а стойкость держится на непредсказуемости ГПСЧ.

## Блочные шифры и режимы

- **Блочный шифр** шифрует блоками фиксированного размера (у нас 8 байт, у AES 16). Если данные не кратны блоку, нужен **паддинг**. PKCS#7: дописываем $N$ байтов со значением $N$.
- **ECB**: каждый блок шифруется независимо. Одинаковые блоки дают одинаковый шифр, и структура данных видна («ECB-пингвин»).
- **CBC**: $c_i = E(p_i \oplus c_{i-1})$, $c_{-1} = IV$ (случайный вектор инициализации). Одинаковые блоки дают разный шифр.

## Сеть Фейстеля

Блок делим на половины $L, R$ по 4 байта. Раунд с ключом $k_i$:

$$L' = R, \qquad R' = L \oplus F(R, k_i).$$

Обратный раунд:

$$R = L', \qquad L = R' \oplus F(L', k_i).$$

$F$ вычисляется от **известного** значения $L' = R$, поэтому её не нужно обращать. Расшифрование — те же раунды с ключами в обратном порядке.

Пример: $L = 1$, $R = 2$, $k = 5$, $F(2, 5) = 1401181143$:

$$(1, 2) \to (2,\; 1 \oplus 1401181143) = (2, 1401181142) \to (1401181142 \oplus F(2,5),\; 2) = (1, 2).$$

## Ответы на вопросы самопроверки

1. **Три условия Вернама: какое нарушено в StreamCipher?** Нарушено условие 1: гамма не истинно случайная, она полностью определяется seed через предсказуемый `random.Random`. По сути нарушено и условие 2: настоящий ключ — короткий seed, а не гамма длиной с сообщение. Последствия: seed можно перебрать, по куску известного текста можно восстановить гамму и предсказать её продолжение. Если один seed использован для двух сообщений, нарушается и условие 3, и работает атака $c_1 \oplus c_2 = p_1 \oplus p_2$.
2. **Вывод $c_1 \oplus c_2 = p_1 \oplus p_2$:** $c_1 \oplus c_2 = (p_1 \oplus k) \oplus (p_2 \oplus k)$; по ассоциативности и коммутативности $= p_1 \oplus p_2 \oplus (k \oplus k)$; по $a \oplus a = 0$ получаем $= p_1 \oplus p_2 \oplus 0$; по $a \oplus 0 = a$ получаем $= p_1 \oplus p_2$.
3. **Почему Фейстелю не нужна обратимость F?** $F$ участвует только как «маска» для XOR, а аргумент $F$ (правая половина) переходит в выход без изменений. При расшифровании мы знаем этот аргумент, снова вычисляем ту же маску $F(R, k_i)$ и снимаем её XOR-ом. Обращать саму $F$ не нужно.
4. **Чем `secrets` отличается от `random`?** `random` — детерминированный ГПСЧ: по seed или по 624 подряд выходам вихря Мерсенна восстанавливается состояние, а с ним и все будущие числа. `secrets` берёт энтропию из ОС (CSPRNG): по предыдущим выходам невозможно предсказать следующие, поэтому он подходит для ключей.
